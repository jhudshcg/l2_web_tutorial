Responsive layouts

A responsive layout adapts to the space available. Start with a clear small-screen layout, then add columns when there is room.

Why does a layout need to change?

A row of three products may fit comfortably on a laptop. On a phone the same row could make the text too cramped. A responsive page rearranges the same content to use the available space.

The viewport is the area where the browser displays the page. In VS Code, a narrow integrated browser panel gives you a narrow viewport even on a large monitor. Widen the preview panel to give the page more room.

1. Meet the container and its children

In your Home page, <div class="cards"> is a parent container. The three articles immediately inside it are its direct children. Put Grid on the parent to arrange those children.

Flexbox is useful for arranging items along a row or column, such as navigation. Grid is useful for rows and columns, such as product cards. Both can wrap or adapt; this is a starting guide, not a strict rule.

Predict a simple layout

Imagine three cards. With grid-template-columns: 1fr;, they sit one below another. With grid-template-columns: 1fr 1fr;, there are two equal columns: two cards on the first row and the third on the next row.

You are dividing the available space into equal shares, not calculating exact pixel widths. The browser works out the widths for you.

Why responsive design matters to your client

A fan may discover the latest album on their phone, then look at merchandise on a laptop. Both visits should make it easy to read the content and use the links. Tiny text, overlapping cards or sideways scrolling can make the fan give up.

Grid, Flexbox and media queries let the same pages adapt to the space available. You maintain one set of content, while visitors get a layout that fits. This directly supports the brief’s requirement to work well across browsing devices.

2. Add responsive layout rules

Add the rules below at the end of your existing css/style.css. Keep the earlier CSS. Work in stages: add the two nav rules and check the links; add the .cards rule and check the cards; then add both @media blocks and change the preview width. Your HTML from step 3 already has the matching classes.

css/style.css — append after existing rules

nav {
  display: flex;
  flex-wrap: wrap;
  gap: 0.75rem;
  align-items: center;
}
nav a {
  padding: 0.5rem;
}
.cards {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}
@media (min-width: 600px) {
  .cards {
    grid-template-columns: repeat(2, 1fr);
  }
}
@media (min-width: 900px) {
  .cards {
    grid-template-columns: repeat(3, 1fr);
  }
}
  • display: flex puts the navigation’s links in a row by default.
  • flex-wrap: wrap lets links move to another line instead of spilling off the screen.
  • gap adds space between items; align-items: center aligns them across the row.
  • display: grid creates a grid. 1fr means one share of the available grid space.
  • repeat(2, 1fr) creates two equal columns. Three equal columns use repeat(3, 1fr).
  • A media query applies rules only when its condition matches. min-width: 600px means a viewport at least 600 CSS pixels wide.

The base layout has one column. At 600px it becomes two. At 900px, both queries match, but the later equally specific rule gives three columns. These widths are examples: choose breakpoints where your own content needs a change.

Try it in your own page

  1. Open Home in VS Code’s integrated browser. Drag the divider beside the preview to make it narrow, then wider.
  2. Use your browser’s responsive/device view if available. Try widths of 360, 768 and 1024 CSS pixels.
  3. Check the number of columns: one, two and three at those example widths.
  4. Check that navigation wraps, text is readable and images stay inside the page.
  5. Temporarily change gap to 2rem. Predict, then check the result.

Expected result: the same content changes arrangement without needing separate mobile HTML.

Check your understanding

My grid still shows one column on a wide screen. What should I inspect?

Check that the parent has class="cards" (plural), the articles are directly inside it, your media-query braces are closed, the stylesheet is saved and the browser is wide enough.

Should I use lots of spaces or a table to arrange the cards?

No. Spaces are not a layout system, and tables describe data. Use Grid or Flexbox for page layout.

Spot the error

Why does the wide-screen rule get ignored?

The base rule creates one column. You expect three columns in a 1024px-wide viewport, but this media query contains an invalid width value.

Broken example — find the mistake

.cards {
  display: grid;
  grid-template-columns: 1fr;
}
@media (min-width: 900) {
  .cards {
    grid-template-columns: repeat(3, 1fr);
  }
}
Need a hint?

Compare the width value with the working media query in the lesson. What follows the number?

Show the corrected code and explanation
@media (min-width: 900px) {
  .cards {
    grid-template-columns: repeat(3, 1fr);
  }
}

Replace the media-query block, keeping the base rule. Test below 900px and at 1024px. Measure the preview viewport, not the width of the whole monitor.
