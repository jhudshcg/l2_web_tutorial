Forms and validation

Build the front end of a contact form: name, email, subject and message. Let the browser check it for you.

1. What a form does

2. Build the form

Every field needs a label and an input. Match the label’s for to the input’s id.

Try it: the contact form

Edit the code

Result

Press Send message with empty fields. Then delete a required and try again. In your own file, this goes inside main in contact.html.

  • select is a dropdown. Each option is a choice. The first empty option makes the visitor choose.
  • textarea is a multi-line box. It is not self-closing.
  • type="submit" checks the form, then sends it.

3. Let the browser check it

Browsers have built-in validation. Add an attribute and the browser stops a bad entry and shows a message. No JavaScript is needed.

Validation attributes
Add thisThe browser checks
requiredThe field is not empty
type="email" "url" "number"The value looks like that type
minlength maxlengthHow many characters
min maxThe lowest and highest number
patternThe value matches a pattern (advanced)

Try it: make a field strict

Try email with “hello”, or number with min 1 and max 10 and the value 50. minlength and maxlength work on text-style types. min and max work on number.

4. Style the form

Plain forms work, but spacing and clear focus make them easier to use. Change the settings and watch the CSS.

Try it: style the fields

Click into a field to see the focus outline. Never remove the outline without replacing it: keyboard users need it.

Show errors after the visitor types

:user-invalid styles a field only after the visitor has used it. Plain :invalid can show red before they start.

input:user-invalid,
textarea:user-invalid {
  border-color: #b3261e;
  background: #fff1f0;
}

Type “hello” in the validation lab’s email field and click away. The border turns red.

Test your form

  1. Click Send message with everything empty. Expect a message on the first field.
  2. Enter a name and hello as the email. Expect an email-format message.
  3. Leave Subject on “Choose a subject…”. Expect a message.
  4. Click the word Email. The cursor should jump to that field.
  5. Fill everything in with made-up details and send.

Expected result: the page reloads and your answers appear in the address bar after a ?. That is the form’s data, labelled by each name. A real inbox needs a server or service. That is an optional extension.

Spot the error

Why does clicking the label not focus the email field?

You can type in the field, but clicking “Email” does not move the cursor into it.

Broken example — find the mistake

<label for="email">Email</label>
<input id="visitor-email" name="visitor-email"
       type="email" required>
Need a hint?

Compare the label’s for value with the input’s id value.
