Test and publish

Check your site as a visitor would. Record what really happens, fix it, then put it online.

1. Test, record, fix, retest

Write the expected result first. Fill in the actual result after you test.

Test all of these on every page:

Every linkImages loadPhone widthTab key worksFormsAnother browser

Then run the HTML checker and CSS validator. They find typos. They do not replace testing with people.

Ask real people

You know where everything is. A visitor does not. Ask at least three people to find a product and use the contact form. Record what they say.

2. Prepare the full project

ContentAt least five pages: client, products, news, latest work and a contact form.
SpeedResize and compress large images. Check how they look and load.
SearchA useful title, clear headings and descriptive links on every page.
FeedbackAsk three people to use the site. Record their feedback and your changes.

Last, review each client requirement: met, partly met or still to do.

3. Publish and hand in

  1. Uploadthe whole folder. Keep paths and names.
  2. Retestopen the live URL and repeat key tests.
  3. Capturescreenshots with the address bar showing.
  4. Hand inWord evidence, proposal slides, website ZIP, live URL.

The ZIP holds only the website files and assets. Use the route agreed in class. The GitHub Pages quickstart explains one option. Keep personal information out of the published site.
