Pages with meaning

Semantic HTML uses elements whose names describe their purpose. It gives your page a clear structure for people and software.

From a few words to an organised page

You can already add headings, paragraphs, lists, links and images. Imagine placing these on a page for a fan: they need to recognise the site, find the menu and get to the main information. The next elements group your content by its job.

Semantic means “to do with meaning”. A nav tells the browser “these are navigation links”. You still put familiar elements such as a and p inside the larger groups.

1. Give the page meaningful parts

header — site introduction
nav — main navigation links
main — this page’s main content
h1 — page heading
section — a topic, normally with a heading
article — a self-contained item, such as a news story
footer — closing information

Use one visible main per page. For these simple pages, use one clear h1, then h2 for sections and h3 for items inside those sections. Choose heading levels for structure; CSS changes their size later.

div is a general container when no more meaningful element fits. span groups a small piece of text within a line. They do not describe a special purpose. Semantic elements do not automatically create columns or guarantee accessibility.

Why give HTML meaning?

A page built entirely from div elements may look similar, but its structure says less about what each part does. Meaningful elements such as nav and main give assistive software useful landmarks. That can help a screen-reader user move straight to navigation or main content.

The names also help you find your way through your own code. If you need to fix the menu next week, the nav is a clear place to look. Combine semantic elements with logical headings, clear link text and keyboard testing; the tags alone do not make the whole page accessible.

2. Structure your home page

Replace everything between <body> and </body> with this. Keep the body tags and the existing head. Keep your album image file. This larger example replaces the practice paragraphs from earlier; save a backup copy outside the website folder first if you want to keep them.

index.html — replacement body content

<header>
  <p>Alex Rivers • Indie music</p>
  <nav aria-label="Main navigation">
    <a href="index.html" aria-current="page">Home</a>
    <a href="contact.html">Contact</a>
  </nav>
</header>
<main>
  <h1>Meet Alex Rivers</h1>
  <p>Alex is a fictional musician who makes upbeat indie music.</p>
  <section class="hero">
    <h2>Latest release: Morning Light</h2>
    <p>A new collection of songs about fresh starts.</p>
    <img src="images/album.svg"
         alt="Morning Light album cover: a yellow sun above teal hills"
         width="600" height="400">
  </section>
  <section>
    <h2>Explore the music</h2>
    <div class="cards">
      <article class="card">
        <h3>Morning Light</h3>
        <p>An upbeat album for a new day.</p>
      </article>
      <article class="card">
        <h3>City Walk</h3>
        <p>A single inspired by evening walks.</p>
      </article>
      <article class="card">
        <h3>Live Sessions</h3>
        <p>Acoustic versions of favourite tracks.</p>
      </article>
    </div>
  </section>
</main>
<footer>
  <p>Alex Rivers — fictional practice website.</p>
</footer>

class="card" labels elements so CSS can style them as a group. You can reuse a class. aria-label gives the navigation an accessible name; aria-current="page" identifies the current page to assistive technology.

Pause before making another page

  1. Find main in the code. Find the main heading inside it.
  2. Change only the words in that heading. Save and check the preview.
  3. Find one article. Change only its description, then check again.

The new containers still hold the headings and paragraphs you already know. It is normal for the page to look mostly the same before CSS is added.

3. Make the second page

  1. Save a copy of index.html as contact.html in the same folder. Keep the original too.
  2. Change the copy’s title to Alex Rivers | Contact.
  3. Replace the content inside main with <h1>Contact Alex</h1> and a paragraph explaining that a practice form will go here.
  4. In the copy’s navigation, move aria-current="page" from Home to Contact. Keep only one current-page marker.
  5. Save both files. Open Home and use the links to go to Contact and back.

Try it

Read your headings in order. Can you understand the page without reading every paragraph? Compare the structure to your wireframe.

Expected result: both pages open through navigation. Home shows a latest-release section and three catalogue items. They will still stack vertically until you add CSS.

Check your understanding

Are head and header the same thing?

No. head contains page information such as the tab title and stylesheet link. header is visible introductory content in the body.

What is the difference between class and id?

A class can be used on many elements. An id identifies one element and must be unique within a page. Later, a label will use an input’s id to connect to it.

Apply it to your project

Plan at least five pages. Include Home, a product display and Contact with a form. Decide where visitors will learn about the client, browse their work and read news. Produce desktop and mobile wireframes for every page. Reuse consistent navigation, then change each page’s title and main content.

Spot the error

Why does the Contact link open a missing page?

Your website folder contains index.html and contact.html. The Home link works, but Contact does not reach your contact page.

Broken example — find the mistake

<nav aria-label="Main navigation">
  <a href="index.html">Home</a>
  <a href="contacts.html">Contact</a>
</nav>
